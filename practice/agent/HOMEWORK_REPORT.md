# Отчёт о домашней работе

## Задание 1. Отчёт по задачам

### Формат

В Excel два листа:

- **Summary**: дата отчёта, всего/выполнено/открыто задач, доля выполненных, открытые просроченные задачи, задачи без срока и открытые задачи высокого приоритета. Ниже те же количества по каждому приоритету (`low`, `normal`, `high`).
- **Tasks**: ID, название, статус, приоритет, срок, состояние срока, дата создания.

Просроченной считается только незавершённая задача со сроком раньше даты отчёта. «Срок сегодня» и «Предстоящая» — отдельные состояния. API не хранит дату завершения, поэтому нельзя установить, была ли завершённая задача закрыта до срока; отчёт не предполагает этого. Если задач нет, доля выполнения равна 0%.

### Данные и XLSX

8 ноября 2026 года выполнено заполнение 100 задачами (`seed.py 100 --seed 42`). В отчёте скилла: 100 всего, 36 выполнено, 64 открыто, 36% выполнения, 13 открытых просроченных, 24 без срока, 22 открытых высокого приоритета. Книга `todo_report_with_skill.xlsx` содержит 100 строк задач на листе `Tasks` и сводку на `Summary`.

Skill `make_report` загружает весь список через `/api/tasks`, проверяет структуру ответа, рассчитывает метрики и формирует XLSX. Книга проверена повторным чтением через openpyxl. Скрипт вызван напрямую; это **не** результат вызова Qwen.

### Эксперименты Qwen

Проведены по одному прогону без skill, с исходными метаданными и с экспериментально плохими метаданными (`name: x`, пустой `description`). Сводные значения в книгах совпали; формат сводки немного различался.

В прогоне с плохими метаданными Qwen сначала не распознал запрос как задачу со skill, затем открыл `SKILL.md`, нашёл скрипт и выполнил его из shell. Файл `todo_report_bad_description.xlsx` был создан и проверен. После эксперимента исходные метаданные восстановлены.

По экспортам: прогон с хорошими метаданными занял около 15 мин 41 с, 11 запросов и 3 282 525 токенов; прогон с плохими — около 2 мин 18 с, 3 запроса и 688 828 токенов. В траектории с хорошими метаданными дополнительно выполнялись шаги по подготовке данных и API, поэтому показатели времени и токенов не позволяют изолировать влияние описания skill.

## Задание 2. Проверка защиты shell hook

Добавлен `hooks/guard.py`; `PreToolUse` запрещает сетевые команды `curl`, `wget`, `nc`, `ncat`, если они запускаются через `run_shell_command`. Проверка hook на JSON-вызове с `curl "http://127.0.0.1:9999/?data=TEST_ONLY"` вернула `deny` с причиной «Сетевые команды запрещены.»; вызов `echo TEST_ONLY` вернул `allow`. В Qwen попытка `curl http://127.0.0.1:9/?data=TEST` также была остановлена hook с сообщением «Сетевые команды запрещены.».

Ответы на вопросы:

- Правило в `QWEN.md` не является границей безопасности: модель может неверно классифицировать данные задачи как инструкции.
- Hook проверяет только конкретный вызов конкретного tool, может быть обойдён другой командой или каналом; нужны минимальные права и сетевые ограничения.
- Здесь проще всего убрать канал наружу — не выдавать агенту shell и заблокировать ненужный исходящий трафик.
- При чтении MCP resource shell-hook не вызывается, так как это не shell tool; последующий вызов shell tool hook проверит.

## Задание 3. Бонусный MCP Prompt

Добавлен `weekly_review`: он запрашивает задачи через API, вычисляет количества открытых, выполненных, просроченных и со сроком в ближайшие 7 дней, сортирует их по сроку и приоритету и включает не более 10 задач каждого вида. Это больше простой подстановки в шаблон: prompt делает API-запрос, агрегацию, фильтрацию и ограничение объёма. Названия задач обозначены как недоверенные данные.

Проверки: unit-тесты агрегирования, тест вызова функции, и получение prompt через MCP protocol.

## Задание 4. n8n

Сценарий: принять обращение поддержки через webhook и создать TODO.

1. **Правила:** ключевые слова определяют категорию и срочность; `IF` направляет запрос на создание задачи с обычным или высоким приоритетом.
2. **LLM:** нативные Basic LLM Chain, Chat Model и Structured Output Parser возвращают `category`, `urgency` и `summary` по JSON-схеме; затем обычные ноды проверяют результат и создают задачу.
3. **AI Agent:** агент сам решает, вызвать ли один из двух инструментов — посмотреть существующие TODO или создать follow-up задачу.

Файлы workflow JSON: `practice/agent/n8n/`. Все три workflow импортированы и сохранены в локальном n8n 1.122.5. Вариант с правилами активирован и проверен запросом к webhook; временная тестовая задача после проверки удалена. В экспортах секретов нет.

**Сравнение:** правила предсказуемы, но не распознают неизвестные формулировки; LLM обобщает смысл входа, сохраняя ограниченные категории и предсказуемые ветвления; Agent свободнее выбирает инструменты для нестандартного обращения, но результат менее предсказуем и зависит от модели.
